# QAStudio 通用教学平台与后管台设计

## 一、现状确认

- **学生端、教师端**：已实现（预习 / 课中 / 复习 / 习题 / 反馈；教师学情概览、章节配置、导出）。
- **后管台**：**未实现**。目前没有：
  - 用户管理（创建/编辑用户、分配班级、角色）
  - 班级管理（创建/编辑班级、学期）
  - 课程管理（创建课程、章节归属课程）
  - 开课与分配（某课程开给某班级、指定授课教师）
  - 教师上传课程 PPT 的完整流程（模型有 `PptFile`/`PptSlide`，后端暂无上传接口）
- **平台泛化**：当前数据模型隐含「单课程」（计算机网络），章节、题库、知识库、PPT 均未关联「课程」实体，无法支持多门课程并存。

---

## 二、目标：通用教学辅助平台

平台不局限于《计算机网络》一门课，支持：

- **多课程**：如计算机网络、数据结构、电子商务概论等，每门课独立章节/题库/知识库/PPT。
- **多班级、多学期**：班级与学期已有（`Class`），需与课程、教师关联。
- **开课与授课**：同一门课可在一个学期内对多个班级开设，每班可指定授课教师；学生通过「班级 + 开课」确定可见的课程与内容。
- **后管台**：管理员完成用户、班级、课程、开课与分配；教师按课程上传 PPT、管理教学内容；学生端仅看到自己所在班级已开课程。

---

## 三、数据模型扩展（建议）

### 3.1 新增：课程（Course）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | PK | |
| name | string | 课程名称（如「计算机网络基础」） |
| code | string, unique, optional | 课程代码，便于导入导出 |
| description | text, optional | 简介 |
| is_active | boolean | 是否启用 |
| created_at, updated_at | datetime | |

### 3.2 新增：开课/授课（Teaching 或 CourseClass）

表示「某课程在某学期对某班级开设，由某教师授课」。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | PK | |
| course_id | FK → Course | 课程 |
| class_id | FK → Class | 班级 |
| teacher_id | FK → User | 授课教师 |
| term | string | 学期（与 Class.term 可一致或更细） |
| is_active | boolean | 是否有效 |
| created_at | datetime | |

约束：同一 `(course_id, class_id, term)` 可约定唯一，避免重复开课。

### 3.3 现有表挂靠课程

- **Chapter**：增加 `course_id`（FK → Course），必填；现有数据可默认归属一门「计算机网络」课程。
- **PptFile**：已有 `chapter_id`，章节已属课程，无需再冗余 course_id。
- **Question、KnowledgeDocument、KnowledgePoint**：通过 Chapter 归属课程，无需改表。
- **ChapterConfig**：保持按 chapter 配置，章节已属课程即可。
- **PreviewRecord、AnswerRecord、QuestionAsked**：学习行为可按 chapter → course 统计；若需「按课程维度」筛选，可在查询时 join Chapter 取 course_id。

### 3.4 用户与班级、课程的关系

- **学生**：`User.class_id` 表示所属班级；学生可见的「我的课程」= 其班级在该学期内的所有开课（Teaching）。
- **教师**：无 class_id；教师可见的「我的课程」= 其作为 teacher_id 的开课（Teaching）对应的课程（去重）。
- **管理员**：可管理所有用户、班级、课程、开课，不依赖班级/课程归属。

## 四、后管台功能清单

### 4.1 用户管理（仅 admin）

- 列表：分页、按角色/班级筛选、搜索用户名/姓名。
- 创建/编辑：用户名、密码（或仅重置）、显示名、角色（student / teacher / admin）、学生所属班级（class_id）。
- 禁用/启用：可选 is_active 字段；或仅通过「删除」软删（按需）。

### 4.2 班级管理（仅 admin）

- 列表：班级名称、学期、学生人数等。
- 创建/编辑：名称、学期（如 2024-秋）。

### 4.3 课程管理（仅 admin）

- 列表：课程名称、代码、启用状态、章节数等。
- 创建/编辑：名称、代码、简介、是否启用。
- 章节管理（可放在课程下）：章节的增删改、排序、归属当前课程；章节下可再管理知识点（或后续迭代）。

### 4.4 开课与分配（仅 admin）

- 列表：课程、班级、学期、授课教师。
- 创建/编辑：选择课程、班级、学期、授课教师（teacher 角色用户）；同一课程+班级+学期不重复。

### 4.5 教师端增强（teacher / admin）

- **我的课程**：展示当前用户作为授课教师的开课列表（课程名、班级、学期）。
- **按课程上传 PPT**：选择课程 → 选择章节（该课程下）→ 上传 PPTX；后端解析备注、生成 PptSlide，并关联 chapter_id。
- 教学内容配置、学情统计：可按「当前课程」或「当前班级」过滤（已有 class_id 筛选的可保留，并增加 course_id 维度）。

### 4.6 PPT 上传（后端）

- 接口：`POST /api/ppt/upload`（或 `/api/courses/{course_id}/chapters/{chapter_id}/ppt`），multipart/form-data，文件类型限制 .pptx。
- 流程：保存文件 → 解析 PPTX（提取每页备注/文本）→ 写入 PptFile + PptSlide；章节需归属某课程，教师仅能上传自己授课课程下的章节（或 admin 不限）。

## 五、前端结构建议

### 5.1 路由与权限

- `/admin`：后管台布局（仅 role === 'admin'）。
  - `/admin/users`：用户管理。
  - `/admin/classes`：班级管理。
  - `/admin/courses`：课程管理（含章节入口）。
  - `/admin/teachings`：开课分配。
- `/teacher`：保留现有学情、配置；增加「我的课程」、「上传 PPT」入口（或「教学内容」下按课程选章节再上传）。
- `/student`：可选「我的课程」入口，进入后选一门课再进入预习/课中/复习/习题（或默认只开一门课时直接进当前课程）；多课程时由后端根据 class_id + 开课返回可选课程列表。

### 5.2 登录与首页跳转

- 学生 → `/student`（或 `/student/courses` 选课后再进具体课程）。
- 教师 → `/teacher`（可增加「我的课程」Tab）。
- 管理员 → 可选默认进 `/admin` 或 `/admin/users`。

## 六、实现顺序建议

1. **数据层**：新增 Course、Teaching；Chapter 增加 course_id；迁移脚本将现有章节归属到默认课程（如「计算机网络基础」）。
2. **后端 Admin API**：用户 CRUD、班级 CRUD、课程 CRUD、开课 CRUD；依赖 `require_admin`（仅 admin 角色）。
3. **后端 PPT 上传**：上传接口 + PPTX 解析（备注/文本）写入 PptFile/PptSlide；权限：教师限自己授课课程。
4. **后端「我的课程」与权限**：教师/学生按开课表获取可见课程；章节列表、题库、学情等按 course_id 过滤（可选，或先按现有逻辑，仅后管台与上传按课程）。
5. **前端后管台**：Admin 布局、用户/班级/课程/开课四个管理页（列表 + 表单）。
6. **前端教师端**：我的课程、按课程选章节上传 PPT。
7. **前端学生端**（可选）：「我的课程」入口与课程切换；无多课程时可暂不改。

---

## 七、安全与合规（延续现有约定）

- 学习数据保存 6 个月、标识匿名化；内容由教师审核，新内容不需先审后发（见原框架文档）。
- 后管台仅 admin 可访问；教师只能管理自己授课课程下的内容；学生只能访问自己班级已开课程。

以上设计可使平台从「单课程」扩展为通用教学辅助平台，并补全后管台与 PPT 上传能力；实现时可按阶段迭代，先完成后管台与课程/开课/用户/班级，再补教师端上传与「我的课程」、学生端多课程入口。
