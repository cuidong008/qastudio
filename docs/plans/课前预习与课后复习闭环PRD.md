# 课前预习与课后复习闭环 PRD

## 1. 背景与目标
- 当前课前预习和课后复习流程缺少统一题源、错题闭环与可追踪的数据沉淀。
- 目标是形成“预习-复习-错题本-同类再练”的学习闭环，且题目统一来自提前生成的题库。

## 2. 需求范围
### 2.1 课前预习
- 明确目标：每节课固定展示 3 个“这节课要会什么”。
- 输入材料：
- 讲义：使用已上传 PDF。
- 视频：按章节上传视频，供课前预习使用；未上传时在学生端显示“未上传”。
- 预习单：
- 每章 5-8 道基础题。
- 题型仅限判断题与选择题（单选/多选/判断）。
- 题目来源仅使用预生成题库 `questions`。

### 2.2 课后复习
- 当天回顾：3 分钟回忆卡，必须填写 3 个关键点。
- 巩固练习：基础题 + 变式题 + 1 道综合题，按难度分层推送。
- 错题闭环：错因标注（概念不清/审题错误/计算失误）+ 同类题再练。
- 题目来源仅使用预生成题库 `questions`。

### 2.3 错题本
- 预习、复习、习题训练三类场景的错题统一进入错题本。
- 错题保留场景信息与错因标签，支持拉取同类题继续训练。

## 3. 用户故事
- 学生在课前选择章节后，可看到 3 个学习目标、PDF/视频状态和预习题并提交作答。
- 学生在课后可提交回忆卡并完成分层练习，做错后可标注错因并获得同类题。
- 教师可按章节配置预习视频链接，确保材料完整。

## 4. 数据与接口设计
### 4.1 数据模型变更
- `chapter_configs`
- 新增 `preview_video_url`：章节预习视频地址。
- `answer_records`
- 新增 `scene`：`preview | review | exercise`。
- 新增 `wrong_reason`：`concept | reading | calculation`。
- 新增 `review_records`
- 字段：`user_id`、`chapter_id`、`recall_points(JSON)`、`created_at`。

### 4.2 新增/变更接口
- `GET /api/preview/task/{chapter_id}`
- 返回学习目标 3 条、材料状态（PDF/视频）、预习题列表。
- `POST /api/questions/submit`
- 入参新增 `scene`；返回 `answer_record_id`。
- `POST /api/questions/answer-records/{record_id}/wrong-reason`
- 保存错因标签。
- `GET /api/questions/{question_id}/similar`
- 拉取同类题（同章节/同题型/同难度优先）。
- `GET /api/review/task/{chapter_id}`
- 返回回忆卡规则、基础题、变式题、综合题。
- `POST /api/review/recall`
- 提交 3 条回忆卡内容。

## 5. 前端交互设计
### 5.1 课前预习页
- 展示：学习目标 3 条、材料状态、预习题列表。
- 作答后立即判题；错误题可标注错因并获取同类题。
- 完成后提交预习记录。

### 5.2 课后复习页
- 展示：回忆卡规则与知识点提示。
- 回忆卡 3 输入框，校验必须填写 3 条。
- 展示分层练习列表；错误题支持错因标注与同类题再练。

## 6. 非功能与约束
- 所有预习/复习题必须来自预生成题库，不走临时生成。
- 未登录用户不可提交回忆卡和作答。
- 保持兼容现有错题本入口，避免历史数据丢失。

## 7. 验收标准
- 学生端预习页可看到 3 条学习目标与材料状态。
- 预习题仅出现判断/选择，数量最多 8 道，来源为题库。
- 复习页可提交 3 条回忆卡并完成分层练习。
- 错题可标注 3 类错因并拉取同类题。
- 预习、复习、训练的错题均可在错题本页查看。
