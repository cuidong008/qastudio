# 生成习题：按章节与知识点的当前策略

## 结论概览

- **多章节**：按**章**生成——每章的内容**分别**送给大模型，每章独立生成该章分配到的题数（每章一次请求/任务）。  
  **例外**：**分析题**在多章时采用「多章合并上下文」策略，见 [分析题-多章合并上下文生成方案](./分析题-多章合并上下文生成方案.md)。
- **单章内多道题**：用**同一章**的一份上下文（文档 + 知识点）按**题型分批**调用大模型，每批可能包含多种题型、多道题；**不是**按知识点逐题生成。

---

## 一、多章节时：按章分别生成

### 1.1 接口与任务模型

- 后端接口是**单章节**的：`POST /teacher/chapters/{chapter_id}/questions/generate`（正式生成）、`POST .../questions/generate-preview`（预览）。
- 每次请求只带一个 `chapter_id`，没有「多章节一次请求」的 API。

### 1.2 前端行为（TeacherQuestionBank 生成习题）

- 用户选择多章后，各题型的「最大数量」会**按章节数均分**到每一章（例如 5 章、单选题要 10 道 → 每章 2 道）。
- **预览**：对每个选中的章节 **for 循环**，每章调用一次 `generateChapterQuestionsPreview(chapterId, chapterTaskPayload)`，即**每章一次请求**。
- **正式生成**：若从课程详情等入口按章操作，则是每章调用一次 `generateChapterQuestions(chapter_id, ...)`，每章一个后台任务（`QuestionGenerationTask` 的 `chapter_id` 为单章）。

因此：**多章节 = 每章内容分别送大模型，每章生成该章分配到的题目**；不是把多章内容合并成一次请求。

---

## 二、单章内：一份上下文 + 按题型分批

### 2.1 上下文的构成（`_generate_questions_for_chapter`）

针对**一个章节**：

1. **文档**：该章节下的 `KnowledgeDocument`（最多 30 条），按条拼成「文档：标题（页码）\n 内容」。
2. **知识点**：  
   - 若请求里带了 **knowledge_point_ids**（且属于该章）：只用这些知识点的 title + content 拼进上下文。  
   - 若未带：先用该章**已有**知识点；若该章没有知识点，则先**自动生成**该章知识点（最多 10 条），再用这些知识点拼进上下文。
3. **联网检索**（若有）：按课程名、章节名、知识点抓取的公开网页摘要，追加到上下文。
4. 总长度截断到约 **18000 字符**。

即：单章内即使用户选了「多个知识点」，也是把这些知识点的内容**全部拼成一份 context**，**不会**按「每个知识点单独调一次大模型、生成一题」。

### 2.2 单次调用与分批（batch）

- 该章只有**一份**上述 context。
- 根据「各题型要生成的数量」和 LLM 的 **output token 预算**，用 `_plan_question_generation_batches` 做**分批**：
  - 按题型顺序：single_choice → multiple_choice → judge → blank → qa。
  - 尽量不把**同一题型**拆到多批；只有当某题型题量很大、单批 token 装不下时，才把该题型拆成多批。
  - 每批可能包含**多种题型、多道题**（例如一批里：单选题 10 + 多选题 5）。
- **每一批**用**同一份** chapter context 调用一次 `_build_generate_questions_prompt`，即：**同一章内容、多批请求、每批生成多道题**。
- 不是「按知识点逐题」：不是每个知识点一次请求、每次只生成一道题。

### 2.3 小结（单章）

| 维度           | 策略说明 |
|----------------|----------|
| 上下文范围     | 该章文档 + 该章（或所选）知识点，拼成**一份** context。 |
| 是否按知识点逐题 | **否**。知识点只参与组成这份 context，不按知识点拆请求。 |
| 分批依据       | **题型** + **输出 token 预算**；每批同一份 context，生成多道题（可能多题型）。 |

## 三、流程简图

```
用户选择：课程 + 多章 + 各题型数量（可选知识点）
                    │
                    ▼
        前端：按章数均分各题型数量
                    │
    ┌───────────────┼───────────────┐
    ▼               ▼               ▼
 章节 A           章节 B           章节 C
    │               │               │
    ▼               ▼               ▼
 该章文档+知识点   该章文档+知识点   该章文档+知识点
 拼成 context_A   拼成 context_B   拼成 context_C
    │               │               │
    ▼               ▼               ▼
 按题型分批        按题型分批        按题型分批
 每批用 context_A  每批用 context_B  每批用 context_C
 调 LLM 生成多题   调 LLM 生成多题   调 LLM 生成多题
```

## 四、相关代码位置（便于核对）

| 说明           | 位置 |
|----------------|------|
| 单章生成入口   | `backend/app/api/teacher.py`：`_generate_questions_for_chapter` |
| 章节 context   | 同上：`r_docs`（文档）+ `kp_rows`（知识点）+ `online_context`，拼成 `context` |
| 知识点选用     | 同上：`selected_kp_ids` 若存在则只查这些；否则用章节已有或自动生成 |
| 分批规划       | `_plan_question_generation_batches(limits, batch_output_budget)` |
| 每批调用       | 同上函数内：`_build_generate_questions_prompt(chapter_title, context, ... batch_limits)` |
| 多章预览       | `frontend/.../TeacherQuestionBank.tsx`：循环 `targetChapterIds`，每次 `generateChapterQuestionsPreview(targetChapterIds[i], ...)` |
| 单章任务       | `_run_question_generation_task(task_id)`：一个 task 对应一个 `chapter_id` |

---

总结：**按章**是「每章内容分别送模型、每章生成自己的题」；**单章内**是「整章一份上下文，按题型/批生成多道题」，**不是**按知识点逐题生成。
