# 题库管理增加题型「分析题」修改方案

## 一、需求简述

- **题型名称**：分析题  
- **题型 key**：`analysis`（与现有 `single_choice`、`qa` 等保持一致命名风格）  
- **与问答题的关系**：结构类似问答题，习题包含 **题干、答案、解析** 三部分；差异在于分析题需符合工程教育认证标准，题干和答案一般**分点、内容较长**。  
- **展示与判分**：与问答题一致——文本作答、语义判卷（或人工复核）。

---

## 二、涉及模块与修改点

### 1. 数据层（backend）

| 文件 | 修改内容 |
|------|----------|
| **`backend/app/db/models.py`** | 1）`Question.question_type` 注释中增加 `analysis`。<br>2）**`correct_answer`**：由 `String(32)` 改为 **`Text`**，以支持问答题/分析题的长答案（分点、多段）。<br>3）**题干 `question_text`**：当前已是 **`Text`** 类型，无需修改，已支持分析题的长题干。 |
| **数据库迁移** | 新增迁移：将 `questions.correct_answer` 从 `VARCHAR(32)` 改为 `TEXT`。 |

**字段类型说明**：

- **题干 `question_text`**：模型中已定义为 `Column(Text, nullable=False)`，本身即支持长文本，分析题的长题干无需改库。
- **答案 `correct_answer`**：当前为 `String(32)`，问答题导入已用 `max_len=64` 截断。分析题答案「分点、内容较长」，方案中**明确将 `correct_answer` 改为 `Text`**，统一支持长答案，兼容现有短答案（单选/多选/判断仍为短字符串）。

| 文件 | 修改内容 |

#### 2.2 题型归一化与生成习题

| 文件 | 修改内容 |
|------|----------|
| **`backend/app/api/teacher.py`** | 1）**`_to_question_type()`**：增加映射，如 `"analysis"、"分析题"` → `"analysis"`。<br>2）**生成习题**：<br>   - 请求体/默认配置中增加 `analysis_max`、`analysis_difficulty_score`。<br>   - **`_build_generate_questions_prompt()`**：题量上限与难度说明中增加「analysis(分析题)」；输出 JSON 的 `type` 允许 `analysis`；在「要求」中单独写清：分析题需符合工程教育认证，题干与答案宜分点、可较长。<br>   - **`type_order`**、**`per_question_token_est`**：增加 `"analysis"`（分析题 token 估计可略大，如 300）。<br>   - 各题型计数与上限判断（如 `created_by_type`、按 type 的 limit）中增加 `analysis`。 |

#### 2.3 导入习题

| 文件 | 修改内容 |
|------|----------|
| **`backend/app/api/teacher.py`** | 1）导入 prompt 中：`question_type` 允许 `single_choice | multiple_choice | judge | blank | qa | analysis`；说明分析题题干/答案可分点、可较长。<br>2）解析 JSON 时：`q_type == "analysis"` 时与 `qa` 同样处理；因 `correct_answer` 已改为 Text，长答案不再截断，存完整内容。 |

#### 2.4 试卷生成与组卷

| 文件 | 修改内容 |
|------|----------|
| **`backend/app/api/teacher.py`** | 试卷相关 DTO 与默认配置（数量、每题分数）中增加 `analysis` 题型，与现有 qa/blank 等一致。 |

#### 2.5 题目列表与提交判卷

| 文件 | 修改内容 |
|------|----------|
| **`backend/app/api/questions.py`** | 1）`list_questions` 的 `question_types` 描述中注明支持 `analysis`。<br>2）`submit_answer`：当 `question_type in {"qa", "blank", "analysis"}` 时走语义判卷（与问答题一致）；`correct_answer` 已为 Text，传入判卷服务的标准答案为完整长文本。 |
| **`backend/app/services/llm_grading_service.py`** | **`grade_qa_or_blank()`**：`qtype` 允许 `"analysis"`，与 `qa` 使用同一套语义判卷逻辑（题干 + 标准答案 + 学生答案）。 |

#### 2.6 预习接口（可选）

| 文件 | 修改内容 |
|------|----------|
| **`backend/app/api/preview.py`** | 当前预习题仅包含 `single_choice, multiple_choice, judge`。若产品希望预习题也包含分析题，在 `Question.question_type.in_(...)` 中加入 `"analysis"`；否则可不改。 |

## 三、工程教育认证与出题要求（Prompt 层）

在**生成习题**与**导入习题**的 LLM prompt 中，对「分析题」单独说明，例如：

- 分析题需符合工程教育认证要求，题干与答案宜**分点、条理清晰**，内容可较长。  
- 题干可包含背景、条件、要求；答案为标准参考答案，可分多段、多要点。  
- 解析可说明得分要点或拓展说明。  

数据模型仍为：题干 `question_text`（已是 Text）、答案 `correct_answer`（改为 Text）、解析 `explanation`（已是 Text），无需新增字段。

## 五、建议实施顺序

1. **数据层**：将 `correct_answer` 改为 Text，并编写、执行迁移；题干 `question_text` 已是 Text，无需改。  
2. **后端**：config → teacher（_to_question_type、生成、导入、试卷）→ questions → llm_grading_service → preview（可选）。  
3. **前端**：TeacherQuestionBank（类型与题库管理全流程）→ TeacherChapterQuestions → client 类型 → 学生端展示 → TeacherCourses（若有需要）。  
4. **联调**：创建/导入分析题 → 组卷 → 学生作答与语义判卷。

按上述顺序可实现「分析题」题型在题库管理、组卷、作答与判卷上的完整支持，并与问答题在展示和判卷上保持一致，仅在题目内容长度与工程认证要求上通过 prompt 区分。
