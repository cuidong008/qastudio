# 互联网试卷 + 分析题：与习题生成一致方案

## 背景与问题

生成试卷时若选择「互联网」题库且配置多道分析题，此前存在：

1. **Token 估算**：互联网试卷生成使用独立的 `generation_token_est`，未包含 `analysis`，分析题按默认 120 估算，与习题生成 1800 不一致，导致总 token 低估、多道分析题时不易触发分批，单次请求易超长。
2. **Prompt**：`_build_generate_paper_prompt` 的 JSON 格式仅包含 `single_choice|multiple_choice|judge|blank|qa`，未要求生成 `analysis` 题型。
3. **答案归一化**：`_normalize_internet_paper_candidate_item` 对非选择/判断题统一 `_trim_answer(..., max_len=32)`，分析题长答案被截成 32 字。

## 目标

与「习题生成」一致：分析题在 token 估算、分批逻辑、prompt 要求、答案长度上按长文本题型处理。

## 修改项

### 1. Token 估算（`_generate_internet_questions_for_paper`）

- 在 `generation_token_est` 中增加：`"analysis": 1800`（与 `_plan_question_generation_batches` 中 `per_question_token_est["analysis"]` 一致）。
- 效果：多道分析题时 `estimated_output_tokens` 会正确增大，触发 `_plan_question_generation_batches` 分批，单批分析题数量受预算限制，避免单次输出过长。

### 2. 互联网试卷生成 Prompt（`_build_generate_paper_prompt`）

- 在题型说明中增加 `analysis`：`"type": "single_choice|multiple_choice|judge|blank|qa|analysis"`。
- 在要求中补充：分析题(analysis) 的 `question_text`、`correct_answer` 可分点、可较长，符合工程教育认证风格；`options` 传 `[]`。
- 可选：在 JSON 示例中增加一条 analysis 示例项，便于模型输出规范。

### 3. 互联网候选题归一化（`_normalize_internet_paper_candidate_item`）

- 对 `q_type == "analysis"`：答案不按 32 字截断，使用完整 `correct_answer`（或与本地/习题一致的大上限，如 50000）。
- 实现方式：在分支中先区分 `analysis`，再对 blank/qa 使用原有 `_trim_answer(..., 32)`；analysis 使用 `str(item.get("correct_answer") or "").strip()` 或 `_trim_answer(..., max_len=50000)`。

## 涉及文件

- `backend/app/api/teacher.py`
  - `_generate_internet_questions_for_paper`：`generation_token_est` 增加 `"analysis": 1800`。
  - `_build_generate_paper_prompt`：题型与要求中增加 analysis 说明。
  - `_normalize_internet_paper_candidate_item`：analysis 题型答案不截断（或大上限）。

## 4. 分析题注入章节内容（与习题生成一致）

当题目来源为「互联网」且题型配置中包含分析题时：

- 在调用混合题型生成前，先拉取所选章节的合并内容：`_build_merged_context_for_chapters(db, course_id, chapter_ids)`。
- 若 `merged_context` 非空，则用与习题生成相同的 prompt（`_build_generate_analysis_only_prompt`）单独调用大模型生成分析题，要求符合工程教育认证、题干与答案分点可较长。
- 将生成的分析题转为与互联网试卷一致的字典格式（含 `question_type`、`question_text`、`correct_answer`、`difficulty_score`、`score`、`source="internet"` 等），作为 `pre_generated_analysis` 传入 `_generate_internet_questions_for_paper`。
- `_generate_internet_questions_for_paper` 增加参数 `pre_generated_analysis: list[dict] | None = None`：若传入则规划批时把分析题数量视为 0（不再在混合批中生成分析题），最终组卷时分析题直接使用预生成列表，不足则记入 `insufficient_types`。

这样，互联网试卷中的分析题与习题生成一致：**会传入所选章节的全部合并内容，并明确要求符合工程教育认证**；其余题型仍由原互联网混合 prompt 生成。

## 小结

| 项目         | 修改前                     | 修改后（与习题生成一致）           |
|--------------|----------------------------|------------------------------------|
| 分析题 token 估算 | 默认 120                   | 1800                               |
| 分批         | 多道分析题易单批、易超长   | 按 1800 估算后正常分批             |
| Prompt       | 未要求 analysis            | 要求 analysis，题干/答案可长       |
| 答案保存     | 截断 32 字                 | 分析题保留长答案                   |
| 章节内容     | 不传入                     | 分析题单独用 merged_context 生成   |
| 工程教育认证 | 仅一句风格描述              | 与习题一致：分点、条理、可较长     |
