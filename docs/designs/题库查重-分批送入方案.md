# 题库查重 - 分批送入方案

## 背景

查重时按「章节 + 题型」分组，每组内题目会一次性拼成一个大 prompt 送给大模型。若某组题目过多，会超出模型 context 或导致超时。需要按题型区分单题 token 预估值，并分批送入。

## Token 预估值（单题）

| 题型       | 单题约 tokens | 说明 |
|------------|----------------|------|
| 普通习题   | ~250           | 单选题/多选题/判断题/填空题/问答题：题干 + 选项 + 答案，篇幅较短 |
| 分析题     | ~800           | 题干/材料长、多问多子题，单题信息量大 |

## 分批策略

- **普通题型**（单选、多选、判断、填空、问答）：每批最多 **120 道**。
- **分析题**：每批最多 **40 道**。

在 120k 上下文下，上述批次约 3 万、3.2 万 tokens 量级，留足余量且控制单次请求延迟与输出解析负担。

## 实现要点

- **前端**（习题库查看/编辑页 `runDedup`）：
  - 仍按「章节 + 题型」分组；
  - 每组内先做文本完全一致去重，剩余题目再参与语义查重；
  - 对剩余题目按 `batchSize`（分析题 40，其它 120）切批，每批调用一次 `POST /teacher/questions/check-duplicates`；
  - 各批返回的 `groups` 直接合并到最终重复组列表（序号均为全局 1-based，无需转换）。

- **后端**：不要求改；单次请求的 `items` 数量由前端控制在上限内。

## 题型识别

- 列表行 `questionType` 来自接口 `question_type`，为 key（如 `"analysis"`），非中文标签。
- 分析题判断：`questionType === "analysis"`；其余均为普通题型，使用 120 道/批。
